# CAMERA 505

> **Contact-free Adaptive Medical Evaluation & Recording Architecture**
> *Medical-grade wireless sleep sensing platform — WE DON'T SUPPORT 67*

CAMERA 505 (formerly **LIFE**) is a real-time, edge-native cardiorespiratory monitoring and sleep intelligence platform. It pairs a **$5 single-lead ECG front-end (AD8232 + Arduino / ESP32)** with **ambient smartphone audio** and **WiFi CSI radar** to detect sleep apnea, arrhythmia and nocturnal anomalies — without a $3k polysomnography lab or 20+ wired sensors.

Built for the *"Signals That Can Change The World"* hackathon.

## What it tries to achieve

1. **Accessible sleep apnea screening.** Over 1B people have undiagnosed OSA. Clinical PSG is expensive, uncomfortable and inaccessible. CAMERA 505 delivers a low-cost alternative (< $15 BOM) to the nightstand.

2. **Multimodal cross-confirmation.** ECG alone is noisy, audio alone is ambiguous. By fusing cardiac electrical signals (R-peaks, HRV, EDR) with respiratory acoustics (80–500 Hz snore resonance, cough bursts, breathing silence) in a shared **512-dim Transformer embedding**, an apnea event is confirmed only when **both modalities agree** (`docs/HACKATHON_PITCH.md:12`).

3. **Personalized, not population-averaged.** Replaces static thresholds (`HR > 100`) with a Gaussian baseline `N(μ, σ)` per patient and a **CatBoost 12-cohort classifier** pre-calibrated on 206k hours (ESRS / SHHS / MESA / UCDDB ...) + online continual adaptation without catastrophic forgetting (`src/backend/app.py:193`).

4. **Contact-free sensing path.** WiFi CSI (52 OFDM subcarriers, ESP-NOW 100 Hz TX → CSI RX) infers respiration from RF chest reflections — no electrode touching the patient (`firmware/camera505_beacon_tx.ino`, `firmware/camera505_radar_rx.ino`, `src/ingestion/wifi_csi_stream.py`).

5. **Local, private, explainable.** All data stays on-device (SQLite + `local_user/{user}/model/`), reports are generated by a local **Ollama LLM** (`llama3.2:1b`) — no cloud leakage (`src/ai/ollama_engine.py`).

> **Disclaimer:** Research / education prototype only. Not a certified medical device. Do not use as sole basis for clinical diagnosis.

## Key Features

| Area | Detail |
|------|--------|
| **ECG Ingestion** | AD8232 → Arduino Uno (`firmware/arduino_uno_camera505_ecg.ino`) or ESP32 (`firmware/esp32_camera505_ecg.ino`) via Serial COM3 @ 115200, or ESP32 WiFi UDP `:3333` (`src/ingestion/serial_stream.py`, `src/ingestion/esp32_wifi_stream.py`) |
| **WiFi CSI Radar** | ESP32 beacon (ESP-NOW Ch.6, 100 Hz) + CSI RX in promiscuous mode, 921600 baud COM4, Savitzky-Golay + zero-crossing → RPM 8–30 (`src/ingestion/wifi_csi_stream.py`) |
| **DSP** | Butterworth 0.5–40 Hz, 50 Hz notch, Pan-Tompkins QRS, RMSSD/pNN50/LF-HF, Poincaré SD1/SD2, ECG-Derived Respiration (EDR) (`src/dsp/ecg_dsp.py`, `docs/ARCHITECTURE.md:16`) |
| **Audio DSP** | 16 kHz PCM → 128-band Mel spectrogram, snore 80–500 Hz ratio, cough explosive detection (`src/dsp/audio_dsp.py`) |
| **Foundation Model** | 30 s windows → 1D/2D CNN encoders → 60 tokens + RoPE → Multimodal Transformer → 512-D embedding; 4 self-supervised tasks (masked recon, InfoNCE, future pred, temporal cons) (`docs/ARCHITECTURE.md:50`) |
| **Personalization** | 12 clinical cohorts (`foundation_models/cohort_baselines_12.json`), Differentiable Soft-F1 adaptive thresholds `θ/τ`, continual EMA updating (`src/models/differentiable_adaptive_threshold.py`) |
| **Backend** | FastAPI + Uvicorn + WebSockets `ws://:8000/ws/live` @ ~30–50 fps, SQLite (`data/life_signals.db`), REST + WS gateway (`src/backend/app.py`) |
| **Frontend** | Next.js 15 + React 19 + Tailwind on `:6767` — live oscilloscope, hypnogram, anomaly radar, night workflow (`idle → active → scoring → report`), history, profile (`life-mobile/app/dashboard/page.tsx`) |
| **Desktop Studio** | Tkinter + Matplotlib 60 FPS oscilloscope + FFT + HRV (`scripts/desktop_ecg_plotter.py`, `src/backend/app.py:789`) |
| **AI Reports** | Ollama local LLM generates empathetic clinical narratives post-session (`src/ai/ollama_engine.py`, `src/backend/app.py:252`) |

```
│  │ ESP32 RX    │◀────────────────┘   │   life-mobile/ :6767         │  │
│  │ (CSI Radar) │──────COM4──────────▶│   + Tk Desktop Plotter       │  │
│  └─────────────┘   921600 baud       └─────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
```

Signal pipeline `README_SIGNALS.md:62`:

```
AD8232 → Arduino/ESP32 (115200 baud) → src/ingestion/serial_stream.py
  → StreamManager 30 s window (7500 pts @250 Hz) → EcgDspProcessor
  → Pan-Tompkins → HRV → Transformer → WebSocket /ws/live → Next.js
```

WiFi CSI pipeline `README_SIGNALS.md:115`, audio `src/dsp/audio_dsp.py`, air-gapped baseline `docs/ARCHITECTURE.md:84`.

## Installation

```bash
# 1. Clone
git clone https://github.com/<you>/camera505.git
cd camera505

# 2. Python deps (recommended: venv)
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate

pip install -r requirements.txt
# Optional: torch CUDA build if you have a GPU — otherwise CPU torch from requirements.txt is fine

# 3. Frontend deps
cd life-mobile
npm install
cd ..

# 4. Initialize local database (creates data/life_signals.db — git-ignored, ~400 MB SQLite WAL)
python scripts/init_db.py
```

Driver (Windows, only if using USB serial):

```bat
:: Install CP210x USB-to-UART driver for ESP32/Arduino clones
install_driver.bat
:: or right-click install_driver_admin.bat → Run as administrator
```

## Running the Platform

### Option A — One-click Windows launcher (Recommended)

```bat
:: Starts backend (:8000) + frontend (:6767) + Ollama check + opens browser
START_CAMERA_505.bat
:: Alternative full launcher:
505
```

Then open `http://localhost:6767/dashboard`.

### Option B — Python orchestrator (cross-platform)

```bash
# From repo root
python scripts/start_all.py
# Auto-opens http://localhost:6767 after ~5 s
# Backend log: [BACKEND], Frontend log: [FRONTEND]
# Ctrl+C stops both
```

What it does (`scripts/start_all.py:96`):
1. Ensures `data/life_signals.db` exists
2. Launches `uvicorn src.backend.app:app --host 0.0.0.0 --port 8000`
3. Launches `npm run dev -- --port 6767` in `life-mobile/`
4. Probes Ollama in background and auto-restarts crashed services

### Option C — Manual (two terminals)

```bash
# Terminal 1 — Backend
python -m uvicorn src.backend.app:app --host 0.0.0.0 --port 8000 --reload

# Terminal 2 — Frontend
cd life-mobile
npm run dev -- --port 6767
# or: npm run dev  (port is hard-coded to 6767 in package.json:7)

# Optional Terminal 3 — Ollama
ollama serve
ollama pull llama3.2:1b   # or llama3, mistral, gemma2:9b (see src/backend/config.py)
```

### Verify it's running

- **Dashboard:** http://localhost:6767/dashboard
- **Login/Quiz:** http://localhost:6767/quiz (9-step intake → CatBoost cohort)
- **Night Session:** http://localhost:6767/dashboard/night (`idle → active → scoring → report`)
- **API Docs (Swagger):** http://localhost:8000/docs
- **System Status:** http://localhost:8000/api/status
- **COM Ports:** http://localhost:8000/api/com_ports
- **WiFi Status:** http://localhost:8000/api/wifi/status
- **Desktop Plotter:** click *Launch ECG Studio* in UI or `python scripts/desktop_ecg_plotter.py` or `GET /api/launch-ecg-studio`

### Running without hardware (synthetic)

The backend auto-selects `source_type`:

- If `COM3` is present → `serial` mode
- Else → `synthetic` mode (`src/backend/app.py:42`)

You can also force a scenario at runtime:

```bash
curl -X POST http://localhost:8000/api/scenario -H "Content-Type: application/json" -d '{"scenario":"sleep_apnea"}'
# healthy_rest | sleep_apnea | arrhythmia | cough_attack | snoring_episode | leads_off
```

### Stopping

`Ctrl+C` in the launcher terminal. The lifecycle handler (`src/backend/app.py:56`) calls `stream_manager.stop_session()` and flushes the night summary.

## Hardware Setup

**Wiring** (`README_SIGNALS.md:195`):

```
AD8232 Module     Arduino Uno / ESP32
─────────────     ──────────────────
  3.3V  ───────▶  3.3V  (NOT 5V!)
  GND   ───────▶  GND
  OUTPUT────────▶  A0
  LO+   ───────▶  D10 (lead-off +)
  LO-   ───────▶  D11 (lead-off -)
  SDN   ───────▶  D12 (shutdown, active-low)
```

**3-electrode placement** (`README_SIGNALS.md:214`):

| Electrode | Color | Placement |
|-----------|-------|-----------|
| RA | 🔴 Red | Right clavicle / right arm |
| LA | 🟡 Yellow | Left clavicle / left arm |
| RL | 🟢 Green | Lower right rib / right leg (ground) |

Tips: clean skin with alcohol, use pre-gelled Ag/AgCl electrodes, power Arduino from a **USB power bank** (not mains laptop) for isolation.

**WiFi CSI pair** (`firmware/README_FIRMWARE.md`): flash `camera505_beacon_tx.ino` to TX ESP32 and `camera505_radar_rx.ino` to RX ESP32 (promiscuous, filter by TX MAC), connect RX via USB @ 921600.

Detailed firmware, DSP and ingestion docs: `explication/` + `README_SIGNALS.md`.

## Training

```bash
# CatBoost ESRS classifier (10k records → foundation_models/catboost_esrs_classifier.cbm)
python -m src.training.train_esrs_catboost
# or via API:
curl -X POST http://localhost:8000/api/training/train_catboost_esrs

# Parallel 12-cohort adaptive threshold training
curl -X POST "http://localhost:8000/api/training/run_parallel?epochs=20"
# or
python -m src.training.parallel_cohort_trainer

# Full pipeline (checkpoints → foundation_models/)
TRAIN_ALL_CAMERA_505.bat   # Windows
# or
python scripts/train_all_pipeline.py
```

Checkpoints are **committed** (`foundation_models/`, `data/catboost_esrs_dataset.csv`) so clones work without retraining (~1h per cohort). Runtime DB `data/life_signals.db` is **ignored** and regenerated via `scripts/init_db.py` (`.gitignore:17`).
